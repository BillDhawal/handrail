# The web UI: the eleven concept screens, built and wired to real data

Date: 2026-11-02. Branch: `web-ui`. Status: in progress.

## What this builds

The eleven screens on `docs/product-concepts.html` become one small local web application,
`handrail ui`, that reads the real capability cards, the real evidence runs and the real
episodes notebook, drives a real replay in the same process with a live view of the browser,
and lets a person mark commits, verify, approve, take over and hand back from the page.

The analogy: the concept art was the architect's drawing of the restaurant. This is the
restaurant with the kitchen plumbed in. Same rooms, same signs, and the food is real.

## Rules that hold

- Rule 1 holds. `serve/web` imports from `schema`, `replay`, `kernel`, `compile`, `surface`
  freely; it imports a model only inside the authoring job, lazily, the way `cli.py` does.
- Replay from the page is the same `ReplayEngine` with the same `Journal`; the page never
  re-executes a dispatched step because it cannot reach the step loop.
- Every rung still proposes. The takeover page is the existing `Console` contract
  (`baton`, `offer`, `handed_back`, `url`, `act`) with a nicer face.
- Secrets never reach the page. Inputs marked `secret` are posted once and masked in
  everything the page reads back, because the page only reads what the `Recorder` wrote.
- Files stay under 250 lines. No build step, no node, no framework on the front end.
- Everything arrives with tests. `make lint && make test` passes before each hand-over.

## Stack

- Server: Starlette on uvicorn (both already in the environment through the `serve` extra;
  added explicitly as a `ui` extra). JSON API plus one WebSocket for live frames and events.
- Front end: `static/index.html` shell, `app.css`, `app.js` (hash router and fetch helpers),
  one small module per page under `static/pages/`. Vanilla ES modules.
- Palette and type from the concept art and the site: bg `#F3F5F2`, ink `#15302B`, muted
  `#56706A`, line `#CBD6D1`, teal `#1F6F63`, brass `#8F6208`; Bricolage Grotesque for
  headings, Atkinson Hyperlegible for text, IBM Plex Mono for ids, hashes and counts. Dark
  mode by `prefers-color-scheme`.

## Package layout

```
src/handrail/serve/web/
  __init__.py
  store.py        reads capabilities/, evidence/runs/, episodes.db into plain dicts (read-only)
  live.py         LiveRun: one replay at a time, in-process, with a recorder that broadcasts
                  events and a screencast loop that broadcasts JPEG frames; WebConsole
  jobs.py         verify, approve, deprecate, and authoring with a web confirm callback
  app.py          Starlette routes, static files, the WebSocket, `build_app(settings)`
  settings.py     Settings dataclass: capabilities dir, evidence dir, episodes path, port
  static/
    index.html app.css app.js
    pages/home.js author.js card.js run.js history.js drift.js catalog.js
tests/serve/web/
  test_store.py test_app.py test_live.py test_jobs.py test_pages_e2e.py
```

CLI: `handrail ui [--port 8090] [--capabilities capabilities] [--evidence evidence/runs]
[--episodes evidence/episodes.db] [--open]`. Registered from `serve/web/app.py:register`.

## API contract (both halves build against this)

All JSON. Errors are `{"error": "message"}` with 4xx.

| method and path | returns |
|---|---|
| GET `/api/summary` | `{capabilities: n, approved: n, runs_today: n, model_calls_on_replay: n, escalations_open: n, needs_a_person: [{run_id, step, expected, since}]}` |
| GET `/api/capabilities` | `[{id, version, title, state, approved_by, approved_at, reliability: {replays, clean}, read_or_write: "read"|"write", inputs: [...], outputs: [...], file, last_run: {run_id, category, started_at} or null, success_rate: 0..1 or null}]` |
| GET `/api/capabilities/{file}` | the full card JSON plus `{versions: [{file, version, state}]}` for siblings sharing the id |
| GET `/api/capabilities/{file}/checklist` | `{verified: bool, commits_confirmed: bool, no_secret_literals: bool, allowed_hosts: [...], plates: n, reasons: [...], approvable: bool}` |
| POST `/api/capabilities/{file}/approve` `{by}` | the updated card or 409 with the `NotApprovable` message |
| POST `/api/capabilities/{file}/deprecate` `{by, why}` | the updated card |
| POST `/api/capabilities/{file}/verify` `{trials: [{...inputs}], check, env: {...}}` | `{job_id}`; progress over the WebSocket as `job.*` events |
| GET `/api/runs?limit=100` | `[{run_id, capability_id, capability_version, started_at, duration_ms, category, code, outcome, classifier_calls, llm_calls, escalated_to_human, steps_ok, steps_total, drift: {steps_resolved, first_choice}}]` newest first |
| GET `/api/runs/{run_id}` | `{result: result.json, events: log.jsonl as list, journal: journal.jsonl as list, chain: {ok, lines}, files: [names], screenshots: [{label, png, txt}]}` |
| GET `/api/runs/{run_id}/files/{name}` | the file (png, txt, jsonl) |
| GET `/api/drift` | `{rungs: [{capability_id, step_id, rung, count, last_run}], healing: [{run_id, step_id, rung, accepted}], calibration: [{question, lo, hi, n, accepted, rate}]}` |
| GET `/api/live` | `{active: bool, run_id, capability_id, state: "idle"|"running"|"paused"|"finished", baton: {owner, history: [...]}, expected: [...], headed: bool, result: RunResult or null}` |
| POST `/api/live/start` `{file, inputs: {...}, env: {...}, headed: bool, classifier: null|"claude"|"laya", console: true}` | `{run_id}` or 409 if one is active |
| POST `/api/live/act` `{action: "take_over"|"hand_back"|"abort", by, screen}` | `{ok: true}` or 409 with the reason |
| POST `/api/author/start` `{goal, entry, allow: [...], inputs: {...}, secrets: [...], id, out, model}` | `{job_id}` or 409 (no key, or busy) |
| GET `/api/author` | `{active, turns: [{index, intent, screen, verb, target, effect}], pending_confirm: {index, what, screen} or null, model_calls, finished, outcome, compiled: file or null, error}` |
| POST `/api/author/confirm` `{decision: "commit"|"navigate"|"stage"|"deny", by}` | `{ok: true}` |
| WS `/ws` | server pushes `{"type": "event", ...recorder event}`, `{"type": "frame", "jpeg": base64, "at": iso}`, `{"type": "baton", owner, history}`, `{"type": "job", job_id, state, line}`; client sends nothing |

Hash routes on the front end: `#/` home, `#/author`, `#/cards/{file}` review (tabs: card,
commits, approve), `#/runs` history, `#/runs/{run_id}` a run (success and failure are the
same page with a different header), `#/live` the live run and takeover, `#/drift`,
`#/catalog`.

## Tasks

1. Backend read side: `settings.py`, `store.py`, `app.py` with the GET routes, static
   serving, CLI registration, the `ui` extra, tests for store and app using
   `evidence/examples` and `capabilities/` as fixtures.
2. Front end: shell, router, all eight page modules against the contract, with fixtures
   stubbed by `fetch` in a tiny `static/dev-data.js` only when `?demo` is in the URL
   (so the page can be looked at without a server during review).
3. Live run: `live.py`, the WebSocket, `/api/live/*`; tests with `NullSurface` and a
   scripted stage set from `tests/replay/test_engine.py`.
4. Jobs: `jobs.py`, verify, approve, deprecate, authoring with a web confirm; tests with a
   scripted model where the existing authoring tests have one.
5. End to end: a Playwright test that starts the app on a free port, opens every hash route,
   asserts the heading and one data element per page, and starts a replay against PLUMBLINE
   when it is up (skipped otherwise). Then a manual pass in a real browser with screenshots.
6. Docs: `docs/HANDOFF.md`, `docs/PLAN.md` code map, README "see it" section, the
   concept page gains a line that it is now built, and the site links the guide.

## Not in scope

Multi-user, auth, remote access (binds to localhost), persistence beyond what the recorder
already writes, editing a card by hand in the page, running two replays at once.
